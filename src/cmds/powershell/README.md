# PowerShell

> Part of [`src/cmds/`](../README.md) — see also [docs/contributing/TECHNICAL.md](../../../docs/contributing/TECHNICAL.md)

## Specifics

- `powershell_cmd.rs` dispatches `rtk powershell <Cmdlet> [args...]` to a per-cmdlet filter (or passthrough), matching real PowerShell aliases (`gci`, `gps`, `gwe`, `sls`, ...) where one exists
- Runs cmdlets via `pwsh -NoProfile -NonInteractive -Command <script>`, falling back to Windows PowerShell 5.1's `powershell.exe` when `pwsh` isn't on `PATH`. Two independent boundaries keep untrusted input from being executed as PowerShell code: (1) the unknown-cmdlet passthrough path allowlists the cmdlet name against `^[A-Za-z][A-Za-z0-9-]*$` via `validate_cmdlet_name` — every real cmdlet/function/alias name matches this shape, anything else is rejected outright rather than quoted, since a command *name* is a token, not a data value; (2) argument values are never quoted-and-interpolated into the script text — `build_powershell_script` embeds a bare `-Flag`-shaped token literally (matched via `SAFE_FLAG_TOKEN`, so it's still parsed as a named parameter) and routes every other value through an `RTK_PS_ARG_<n>` environment variable referenced as `$env:RTK_PS_ARG_<n>`, which PowerShell expands as inert string data with no re-parsing
- Table cmdlets (`Get-ChildItem`, `Get-Item`, `Get-Process`, `Get-Service`, `Get-NetAdapter`, `Get-NetTCPConnection`, `Get-Package`, `Get-WinEvent`, `Get-EventLog`) keep the header and cap data rows via the shared `split_table`/`format_capped_table` helpers, falling back to raw lines when the expected header isn't found (custom `-Property` projections, error output); `group_wrapped_rows` folds `Format-Table -Wrap` continuation lines (and `Get-Counter`'s always-two-line samples) back into the single record they belong to before capping, so a wrapped row is never miscounted or cut mid-record
- List-formatted single-object cmdlets (`Test-NetConnection`, `Get-ComputerInfo`/`Get-SystemInfo`) keep only a handful of high-signal `Key : Value` properties via `filter_keyed_properties`
- `Get-ItemProperty`'s real output is a flat `Key : Value` list (not a table); the filter drops the duplicated `PSPath`/`PSParentPath` registry paths and pulls `PSChildName` to the front so it survives the cap even though PS* metadata commonly prints after dozens of real values
- `Get-Content` keeps a head/tail window for large files instead of `rtk read`'s language-aware filtering, since the content read here isn't necessarily source code
- `Select-String` and `Get-Counter` cap their line count with an overflow note; `Install-Package` keeps only status/outcome lines out of dependency-resolution noise
- Cmdlets with already-minimal output (`Copy-Item`, `Move-Item`, `New-Item`, `Test-Path`, `Remove-Item`, `Join-Path`, `Write-Output`, `Out-String`, `Set-ItemProperty`, `Clear-EventLog`, `Sort-Object`, `Format-Table`), interactive/side-effecting cmdlets (`Start-Process`, `Stop-Process`, `Set-Location`, `Get-Location`), and any cmdlet RTK doesn't specifically recognize all pass straight through unfiltered — like `rtk proxy` — rather than fabricate a filter with nothing meaningful to condense
- Fixtures under `tests/fixtures/powershell/` each start with a `# rtk fixture note: ...` provenance comment (stripped by tests via `strip_fixture_note`) documenting whether the fixture is a real captured-and-anonymized PowerShell output or hand-authored (for cmdlets unsafe to run for real, like `Install-Package`)
